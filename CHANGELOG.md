### Added

- Initial project structure.
- `DetectFormat`: recognizes CDF-1, CDF-2, CDF-5 and NetCDF-4 (HDF5) files from their header.
- Classic reader: `Open` and `NewReader` parse a CDF-1, CDF-2 or CDF-5 file — dimensions
  (including the unlimited dimension), global and variable attributes, and variables with their
  netCDF types. `Variable.Read` and `ReadSlice` read whole variables and hyperslabs with exact
  typed slices; record variables are addressed by record number.
- All header counts, lengths and offsets are validated against the input before allocation; a
  corrupt file yields an error wrapping `ErrCorrupt`, never a panic or an out-of-range slice.
  `FuzzReadHeader` covers the header parser; the fixtures in `testdata/` are generated by
  netCDF-C 4.10.1's `ncgen` and checked against its `ncdump`.
- Classic writer: `NewSchema` with `AddDimension`, `AddVariable` and `SetAttr`/`SetAttrTyped`
  describes a file; `Create` validates it, writes the header exactly as netCDF-C's `NC_begins`
  lays it out, and fills every fixed variable with its fill value. `Writer.Variable(name)`
  writes whole variables and hyperslabs (`Write`, `WriteSlice`), appending and filling record
  slabs past the current record count; `Close` writes the final record count. `_FillValue`
  overrides the type's default. Output is byte-identical to `ncgen` for every model and format
  the classic-only oracle can produce, and `ncdump`/`nccopy -k 1|2|5` read it.
